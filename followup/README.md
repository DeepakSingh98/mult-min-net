# Follow-up: is learning about the journey or the destination?

Code and receipts behind the follow-up post, [Is learning about the journey or the
destination?](https://deepaksingh98.github.io/projects/journey-or-destination/). The post hands gradient descent a
network that already multiplies perfectly and watches what happens.

The lane reports below call these networks "written". The post calls them programmed networks, meaning networks made
by weight-space programming.

## Where each claim comes from

| Claim in the post | Folder | Look at |
|---|---|---|
| A network that multiplies numbers of any length, 870 nonzero weights, no mistakes in 3 million problems | `../anylen/` | `REPORT.md`, `verify_any.py` |
| Training breaks it, the harmless fix (scaling the final layer norm), the gradient's cosine with it (about 1e-10), breaking at 3e-6 on 4-digit and 3e-7 on 100-digit problems, and the confident version breaking at the same distance | `state_signal/` | Experiment 4: `code/e4.py`, `analyze_e4.py`, `REPORT.md`, `TABLES.md` |
| The swap test and how much of the change the gradient predicts (under 1e-27 on the any-length network, 2.5e-8 on the NTT network, 0.15% on a trained Neural GPU, roughly all of it on random networks) | `state_signal/` | Experiment 1: `code/e1.py`, `analyze_e1.py`, `REPORT.md`, `TABLES.md` |
| Networks gradient descent found itself slip by a problem at a time, the programmed ones get every problem wrong within 25 steps, the cosine of 0.4 to 0.6 vs about 1e-10, and untying the last 22 passes (37× larger step) | `journey/` | `PROTOCOL.md` (predictions written before any run), `DECISIONS.md`, `REPORT.md`, `TABLES.md` |
| The figures | `figures/` | one `make_followup_*.py` per figure |

`journey/TABLES.md` is generated by `journey/analyze.py` from the JSON in `journey/results/`. `state_signal/TABLES.md`
holds every number from that lane. Its raw outputs (about 70 MB) are not included.

## Inputs

`inputs/` is shared by both experiment folders (pass `--inputs ../inputs` or the path to it):

- `anylen.npz` and `two_layer.npz` link to the weights already in this repo (`../anylen/weights/`, `../weights/`).
- `ngpu/`: three Neural GPU checkpoints trained by gradient descent on binary multiplication up to 20 bits. Seeds 1
  and 2 learned it. Seed 3 failed and is the "failed seed" control.
- `tf-add-soft-s1.{pt,json}`: a looped transformer from the any-length network's architecture family, trained on
  decimal addition up to 8 digits.
- `ntt_build.py` rebuilds the number-theoretic-transform network's weights (about 30 MB, so not checked in):
  `python3 -B inputs/ntt_build.py OUTDIR 32`.

## Running things

Python with `numpy==1.26.4` and `torch==2.5.1` (the repo's `requirements.txt`). Everything below runs on CPU. The
original runs used cloud CPU VMs and one L4 GPU for the trained networks, through launch scripts that were specific to
that setup and aren't included.

```bash
cd followup/journey
python3 -B analyze.py                                                    # rebuild TABLES.md from results/
python3 -B code/j.py check --inputs ../inputs                            # start-of-run facts
python3 -B code/j.py scan specs/scan5.json OUT --inputs ../inputs --procs 8
python3 -B code/j.py train specs/train5.json OUT --inputs ../inputs --procs 8

cd ../figures
python3 -B make_followup_train.py ../journey/results
python3 -B make_followup_tension.py ../state_signal/TABLES.md
python3 -B make_followup_landscape.py ../../anylen                       # uses the cached grid if present
```

`make_followup_figs.py` draws the wave and butterfly figures and needs the any-length folder, an NTT build and the
Experiment 4 scans (see its docstring). `plate.py` is the site's figure style helper.

## Caveats

- Only three trained networks, on tasks next to the programmed ones (binary multiplication and decimal addition).
- The continued-training runs start a fresh Adam, since the original optimizer state wasn't saved.
- "Strict" means every test problem is right, which is a harsh bar for trained networks. Their failures are mostly one
  or two problems.
